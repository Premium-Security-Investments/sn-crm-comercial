## Alcance verificado

E2 establece que, con `AGT002_CANONICAL_ONLY=true`:

- solo un run `AGT-002` / `agent_ai` / `completed` puede marcarse `canonical=true`;
- los intentos se registran de forma append-only como `queued`, `running`, `completed`, `retry_wait`, `needs_attention` o `unavailable`;
- un error, falta de configuración o falta de capacidad no crea ni presenta un análisis sustituto por reglas;
- el worker conserva el job pendiente con backoff cuando Vig-IA está `unavailable`;
- la reutilización idempotente exige `canonical=true`;
- el selector de análisis actual ignora runs más recientes de reglas y no cae a snapshots históricos;
- un retry posterior fallido o no disponible se expone como `analysis_attempt` separado sin reemplazar el análisis canónico;
- la proyección pública del intento excluye `error_message` para no filtrar mensajes crudos del proveedor;
- la presentación conserva la procedencia tipada (`producer`, `method`, `canonical`) y no permite que `result` la falsifique;
- ambos backends conservan paridad byte a byte.

Con el flag apagado se conserva el comportamiento legacy como rollback funcional y no se consulta la columna `canonical` de la migración 050.
