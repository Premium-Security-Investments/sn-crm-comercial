# Gate E4 — Retrieval documental productivo

Fecha: 2026-07-31

## Estado

`AGT002_DOCUMENT_RETRIEVAL=false`. E4 no se activó.

## Prerequisitos aprobados

- migración 052 aplicada y verificada;
- RLS activa;
- solo `service_role:SELECT` sobre tablas del dominio;
- gate focal retrieval/legal/context: 20/20;
- caso de 14 documentos con 1.466 chunks sobre 14 versiones documentales;
- cero jobs activos;
- E2 y E3 sanas.

## Gate bloqueante

El contrato aprobado exige un canary end-to-end sobre un snapshot representativo de 14 documentos. El único snapshot con 14 documentos ya está ligado idempotentemente al run canónico E2. Reencolarlo después de activar retrieval reutilizaría el run existente y no probaría un nuevo evidence packet ni nuevas citas.

El único snapshot nuevo disponible tiene 9 documentos. Usarlo permitiría probar el camino técnico, pero no cumpliría el tamaño representativo comprometido en el plan.

## Decisiones de seguridad

No se:

- activó retrieval para casos futuros;
- clonó o manipuló un snapshot productivo;
- inventó evidencia humana para forzar una nueva versión de contexto;
- procesó indiscriminadamente el Radar;
- declaró E4 aprobada con evidencia insuficiente.

## Condición de reentrada

E4 podrá continuar cuando exista:

1. un nuevo snapshot real de 14 documentos en una oportunidad ya convertida; o
2. una nueva versión de contexto por respuesta humana auténtica que genere una identidad canónica distinta sobre el snapshot de 14 documentos.

E5 permanece apagada por dependencia de E4. El manifest `legal-corpus-v1` validó 6 fuentes, pero las tablas productivas continúan vacías y no se publicó corpus.
